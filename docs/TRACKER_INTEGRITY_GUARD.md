# 🗂️ トラッカー整合性ガード (T890)

> `data/` 配下の4トラッカー TSV（**課題管理表** `issues_tracker.tsv` / **QA表** `qa_tracker.tsv` / **テスト結果** `test_results.tsv` / **リリース判定** `release_go_no_go_criteria.tsv`）が、Google Sheets の各タブ（CEO 閲覧）の**正本**として壊れていないことを、**人間が手順どおり実行して OK/NG を判断できる**ように定義したガード仕様書。
>
> これらは全レーン（Antigravity / Codex / Claude Code）が追記する。1行でも列数がずれた行・重複ID・不正な状態値・壊れた日付・実在しないタスクへの参照が混じると、**次の Sheets 同期で CEO 閲覧タブが静かに壊れる**。本ガードはそれを同期前に CI で落とす。

---

## 1. 目的

- トラッカー TSV の**構造**（ヘッダ・列数・ID一意・必須セル）を保証する。
- **状態値・日付形式**の正規性を保証する。
- **クロスリファレンス**（課題/QA が参照する WBS タスク、WBS が「記録」と主張する QA-/R- ID）が実在に解決することを保証する。

## 2. 実行方法

```powershell
python scripts/audit_tracker_integrity.py
python -m pytest tests/test_tracker_integrity.py -q
```

監査は `exports/tracker_integrity_audit.{json,md}` に結果を出力し、10仮説すべて PASS で終了コード 0、1つでも FAIL で 1 を返す。

## 3. 10仮説（人間が確認できる観点）

| 仮説 | 内容 | OK と言える条件 |
| :-- | :-- | :-- |
| H1 | 課題管理表の構造 | ヘッダが既定15列と一致し、全データ行が15列（ラグド行=0） |
| H2 | QA表の構造 | ヘッダが既定10列と一致し、全データ行が10列 |
| H3 | テスト結果・リリース判定の構造 | それぞれ9列・13列のヘッダ一致・全行整形 |
| H4 | ID一意 | 4トラッカーとも各ファイル内でIDの重複が0件 |
| H5 | 状態値の正規性 | 課題は open/resolved/accepted_non_blocker/transferred/closed、QAは 回答済/想定済 のみ |
| H6 | 日付形式 | 起票日・解決予定日・更新日が YYYY-MM-DD（空欄は許容） |
| H7 | WBS参照の解決 | 課題の「関連 WBS」・QAの「関連論点」に含まれる T参照がすべて実在の WBS タスクID |
| H8 | 必須セル非空 | 課題: ID/カテゴリ/重要度/状態/タイトル、QA: ID/カテゴリ/質問/状態 が空欄でない |
| H9 | 双方向ドリフト0 | WBS 詳細が「QA-NNN/R-NNN 記録」と主張する ID が、対応トラッカーに実在する |
| H10 | 全体整合 | H1〜H9 がすべて PASS（構造/参照ドリフト0） |

## 4. 判定

- **OK**: `python scripts/audit_tracker_integrity.py` が「総合判定: ✅ PASS」を表示し、`tests/test_tracker_integrity.py` が全件 green。
- **NG**: いずれかの仮説が ❌。監査出力の「詳細」列に、ラグド行ID・重複ID・不正状態・不正日付・未解決参照・空欄セル・欠落IDが具体的に列挙される。

## 5. NG 時の対応

1. **H1〜H3 ラグド行**: 該当行のタブ区切り列数を修正する（TSV編集は UTF-8/CRLF を維持し、編集後に必ず本監査で列数を再検証してからコミットする）。
2. **H4 重複ID**: 採番を修正する（課題=R連番、QA=QA-連番、テスト=TS-連番）。
3. **H5/H6**: 状態値を許容集合へ、日付を YYYY-MM-DD へ正規化する。
4. **H7/H9 参照切れ**: 参照先の WBS/QA/R を実在IDへ修正、または欠落しているトラッカー行を追加する。
5. 修正後に監査とテストを再実行し 10/10 PASS を確認してからコミット・Sheets同期する。

## 6. 補足

- 本ガードは**構造と参照の整合**を保証するもので、各課題/QAの**内容の妥当性**や**未解決ブロッカーの有無**は `scripts/audit_issue_qa_blockers.py` が別途担保する。
- 追記の実務では、本監査を「Sheets 同期の直前ゲート」として実行すると、CEO 閲覧タブへ壊れた行が届くのを確実に防げる。
