# 🧭 WBSライフサイクル網羅性・日程整合ガード (T889)

> `data/WBS.tsv` が **企画 → 設計 → 実装 → テスト → リリース → 実運用 → 保守** の全工程を、確定スタック（レジストラ=**お名前.com** / バックエンド=**Firebase** / DB=**Supabase**）にわたって漏れなく持ち、ステータス・列・日程が壊れていないことを、**人間が手順どおり実行して OK/NG を判断できる**ように定義したガード仕様書。
>
> これまで工程網羅は手動レビュー（`docs/WBS_PROCESS_COVERAGE_AUDIT_2026-06-13.md` / `..._2026-06-25.md`）だけで確認していた。本書はそれを **10仮説の自動監査** に置き換え、ライフサイクルのギャップ・不正ステータス・日程逆転（開始日 > 終了予定日）を CI で落とす。

---

## 1. 目的

- WBS の全タスクが完了したとき、そのまま「企画から保守まで漏れなく開発完了」と宣言できる状態を、機械的に保証する。
- 後段工程（リリース→実運用→保守）と完成判定ゲートがテールから欠落していないことを保証する。
- 日程データの破損（欠落・逆転）を早期に検出する。

## 2. 実行方法

```powershell
python scripts/audit_wbs_lifecycle_coverage.py
python -m pytest tests/test_wbs_lifecycle_coverage.py -q
```

監査は `exports/wbs_lifecycle_coverage_audit.{json,md}` に結果を出力し、10仮説すべて PASS で終了コード 0、1つでも FAIL で 1 を返す。

## 3. 10仮説（人間が確認できる観点）

| 仮説 | 内容 | OK と言える条件 |
| :-- | :-- | :-- |
| H1 | タスク件数とヘッダ | タスクが 50 件以上あり、ヘッダが既定の10列（タスクID〜終了予定日）と完全一致 |
| H2 | タスクID一意 | 重複するタスクIDが 0 件 |
| H3 | ライフサイクル7工程網羅 | 企画/設計/実装/テスト/リリース/実運用/保守 の各工程を示すタスクが**各≥1件**存在（未網羅工程=なし） |
| H4 | 確定スタック網羅 | お名前.com / Firebase / Supabase を扱うタスクが**各≥1件**存在（未網羅スタック=なし） |
| H5 | 必須列に空欄なし | 全行が タスクID・大フェーズ・タスク名・担当・実行エンジン・ステータス を空欄なしで保有 |
| H6 | ステータス正規 | 全行のステータスが「完了 / 実行中 / 未着手」のいずれかのみ |
| H7 | 未完了タスクの日付 | 未完了（実行中/未着手）タスクは開始日・終了予定日を YYYY-MM-DD 形式で両方保有 |
| H8 | 日程の非逆転 | 全行で **開始日 ≤ 終了予定日**（開始日が終了予定日より後の行=0） |
| H9 | 完成判定ゲート | 全WBS完了を束ねる最終判定タスク（総合判定/開発完了/GAリリース閉鎖 等）が存在 |
| H10 | 全体整合 | H1〜H9 がすべて PASS（ライフサイクル/日程のギャップ 0） |

## 4. 判定

- **OK**: `python scripts/audit_wbs_lifecycle_coverage.py` が「総合判定: ✅ PASS」を表示し、`tests/test_wbs_lifecycle_coverage.py` が全件 green。
- **NG**: いずれかの仮説が ❌。監査出力の「詳細」列に、未網羅工程・未網羅スタック・空欄・不正ステータス・日程逆転タスクIDが具体的に列挙される。

## 5. NG 時の対応

1. **H3/H4 未網羅**: 欠落した工程/スタックのタスクを `data/WBS.tsv` に追加する（企画→保守で工程を1つも欠かさない方針）。
2. **H8 日程逆転**: 該当タスクの開始日・終了予定日を修正する（前倒し進行に合わせた再スケジュール時も、開始 ≤ 終了 を維持）。
3. **H5/H6/H7**: 空欄補完・ステータス正規化・日付補完を行う。
4. 修正後に監査とテストを再実行し 10/10 PASS を確認 → `python scripts/generate_wbs_md.py` で `docs/WBS.md` を再生成 → コミット。

## 6. 補足

- 本ガードは工程の**存在**（網羅性）と**日程整合**を保証するもので、各タスクの**中身の妥当性**（受入基準の充足）は `docs/UAT_TEST_SPECIFICATION.md`（T882）と各機能の監査ハーネスが担保する。
- 過去回の手動網羅監査（06-13 / 06-25）は履歴として残すが、現行の網羅判定の正本は本自動ガードとする。
