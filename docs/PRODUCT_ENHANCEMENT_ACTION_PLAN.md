# 🚀 プロダクト強化4大アクション仕様書・設計書 (T960〜T963)

本ドキュメントは、PdMレビューによるヒットプロダクト比較（Linear, Slack, SmartHR, Harvey等）に基づき、PMF深化・参入障壁構築・ワークフロー統合を推進する4大アクションの技術仕様および設計を定義する仕様書です。

---

## 1. Action 1: キラー機能の研ぎ澄まし (T960)

### 1.1 背景と目的
SES・人材企業の最重要ペインである「日次1,000件の営業メール選別・適合人材抽出」へ全プロダクト価値を集中させ、成約時間を3〜4時間から3〜5分（95%以上削減）へと短縮する North Star KPI をダッシュボード最前面に可視化する。

### 1.2 主な仕様
- **North Star KPI の定義**: `営業マッチング成約時間削減率 = (従来平均所要時間 - MightyLINK所要時間) / 従来平均所要時間 >= 95%`
- **プロダクト情報階層の再編**:
  - メイン領域: 営業メールAIマッチング・適合ランキング・リアルタイム新着速報
  - サブ/補助領域: 勤怠CSV集計・社内モチベーション診断（マッチング時の補助コンテキストデータとして活用）

## 2. Action 2: インサイドワークフロー化・Slack/Teams通知 (T961)

### 2.1 背景と目的
ユーザーがWeb画面（`index.html`）を常時監視しなくても、普段業務で利用する Slack / Teams にAIが即時通知・日次サマリを届けることで、スイッチングコストをゼロにする。

### 2.2 主な仕様
- **モジュール**: `src/slack_teams_notification.py`
- **通知トリガー**:
  1. **即時カード通知**: マッチ度スコア **80% 以上** の高適合案件・人材が検出された瞬間に Webhook 経由でカード形式（リッチフォーマット）で通知。
  2. **毎朝9:00 日次ダイジェスト**: 前日取り込み全メール件数、最高マッチ件数、未対応件数を集計して自動投稿。
- **過剰通知防止**: スコア 80% 未満は即時通知せず、日次サマリおよびWebダッシュボードでのみ検索可能とする。

## 3. Action 3: AI自己学習フライホイール (T962)

### 3.1 背景と目的
営業担当がマッチング結果に対して行った「採用（応募/提案）」「却下（見送り）」のフィードバックログ（`email_match_feedback`）をAIプロンプトへ動的にフィードバックし、使えば使うほど企業固有の嗜好に自動最適化される参入障壁（Moat）を形成する。

### 3.2 主な仕様
- **モジュール**: `src/ai_feedback_flywheel.py`
- **学習フィードバック生成ロジック**:
  - 過去の直近フィードバック（過去30日・最大50件）を解析。
  - 「高評価スキル傾向（例: Python 3年以上＋FastAPIが好まれる）」および「却下理由（例: 単価上限超過、フル出社NG、特定FW未経験）」をサマリ化。
  - 次回AIマッチングプロンプトのコンテキスト（Few-Shot / Preference Guidance）へ自動注入。

## 4. Action 4: Pro/Enterprise単価の向上（ミキワメAI連携） (T963)

### 4.1 背景と目的
スキル面（Technical Hard Skills）だけでなく、外部適性診断ツール「ミキワメAI」の適性・性格・ストレス耐性データ（Soft Traits）を組み合わせた「多次元相性判定」を提供し、Standardプラン（¥9,800/月）/ Proプラン（¥29,800/月）および Enterprise プランへのアップグレード動機を強化する。

### 4.2 主な仕様
- **モジュール**: `src/mikiwame_ai_integration.py`
- **評価アルゴリズム**:
  - `総合適合スコア = (スキル一致スコア × 0.6) + (ミキワメ適性相性スコア × 0.4)`
  - エンジニアの適性タイプ（例: 探求・自律型 / 協調・サポーター型）と案件の職場環境（例: 急成長スタートアップ / 堅実な大手プライム案件）のシナジーをAI解説付きで算出。
