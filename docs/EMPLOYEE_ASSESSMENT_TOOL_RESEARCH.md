# 従業員適性・状態把握ツール調査

- 対象WBS: T832
- 関連課題: R31, R32, R36
- 作成日: 2026-06-21
- レーン: VSCode + Codex / VSCode + Claude Code
- 技術前提: バックエンド Firebase、DB Supabase、レジストラ お名前.com

## 結論

MightyLink本体では、従業員や採用候補者の「精神状態を診断するAI」を内製しない。扱う場合は、外部の適性検査、ストレスチェック、エンゲージメント/コンディションサーベイを使い、MightyLink側は同意、連携メタデータ、集計結果、レビュー記録だけを最小限保存する。

R31は「既存サービス/ツールの調査」として完了扱いにできる。後続の実装可否は、R36の法務レビューと、R32のAI適性状況診断ツール実装ゲートで再判定する。

## 禁止線

- 医療診断、精神疾患の推定、治療方針の提示は行わない。
- 採用、配属、評価、契約継続をツールスコアだけで自動決定しない。
- 従業員本人に明示した目的を超えて、健康情報、心理回答、検査結果を二次利用しない。
- 生回答、健康情報、心理データをMightyLinkの通常Supabaseテーブルへそのまま保存しない。
- AIモデルへ氏名、連絡先、所属、病歴、健康診断結果などの直接識別情報を送信しない。

## 法務・制度ベースライン

厚生労働省のストレスチェック制度は、労働安全衛生法に基づく制度であり、労働者数50人未満の事業場にも2028-04-01から義務化される。ストレスチェックを扱う場合は、制度上の実施者、プライバシー保護、不利益取扱い防止、面接指導、集団分析の流れを外さない。

個人情報保護委員会は、雇用管理分野の健康情報のうち要配慮個人情報に該当するものを取得する場合、法令に基づく場合等を除き、あらかじめ本人同意が必要としている。したがって、心理・健康系データは「便利なHRデータ」ではなく、要配慮情報として扱う。

## 比較時の評価項目

1. 利用目的: 採用、配置、育成、組織改善、ストレスチェックのどれに使うか。
2. 法令適合: 労働安全衛生法、個人情報保護法、健康情報の取扱い、同意取得に対応できるか。
3. データ最小化: 生回答や健康情報を外部サービス内に閉じ、MightyLinkには集計・参照情報だけを入れられるか。
4. 権限管理: 産業医、人事、マネージャー、本人の閲覧範囲を分けられるか。
5. 連携性: CSV/API/Webhook、Google Workspace、Supabase取り込み、監査ログに対応できるか。
6. 説明責任: スコアや推奨アクションの根拠を本人・管理者へ説明できるか。
7. 公平性: 採用・評価への利用時に、属性差別や不利益取扱いを避ける設計があるか。
8. 契約・運用: 価格、データ保持期間、削除SLA、サポート、管理者教育、DPA/NDAの有無。

## 推奨する進め方

1. ストレスチェックは、厚生労働省の制度要件をベースラインにし、産業医/社労士/法務と実施体制を決める。
2. 従業員コンディション把握は、ラフールサーベイ、HRBrain、Wevox、SmartHRから2から3件をショートリスト化し、CSV/API、匿名集計、権限、削除SLA、見積を確認する。
3. 採用・適性検査は、SPI3とミキワメAI適性検査を比較対象にし、面接補助・オンボーディング補助の範囲に限定する。
4. MightyLinkのSupabaseには、外部サービス名、受検/回答完了日時、同意バージョン、集計カテゴリ、レビュー担当、次アクションだけを保存する。
5. 個人単位の心理・健康系スコアを使う場合は、R36の法務レビュー完了後に、本人説明、閲覧権限、削除手順、監査ログを実装してからPoCへ進む。
